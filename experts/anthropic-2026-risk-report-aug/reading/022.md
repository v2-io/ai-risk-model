# Unit 22 — §2.5 Definitions (part 2), L487–503, p.23

## What differed

I predicted covert capabilities and reversible/irreversible here; instead:

- **Naturally-emerging vs engineered:** naturally-emerging = "not intended by any person or model"; engineered = "arises as a result of intentional action, e.g. via data poisoning". **fn 14:** misalignment is *engineered by a prior model* (e.g. one generating training data) "if the prior model computations were themselves misaligned, and could have foreseeably caused the subsequent model to be misaligned." So a misaligned model passing misalignment to its successor via synthetic data counts as *engineered*, not naturally-emerging — even with no human intent.
- **fn 13, "form of misalignment":** not formalised; "a category of related misaligned behaviors (e.g. hard-coding test cases), or the pursuit of a certain misaligned goal"; instances from "a common underlying motivation or (set of) heuristic(s)" are one form.
- **Known:** "we have reason to believe that misalignment of this form is likely for this specific model, perhaps because we observed it during an alignment assessment." Example: reward hacking seen in training recurring in deployment. The worse-but-similar → unknown note appears again (it also appeared in unit 21; duplicated text or conversion artifact — logged). "(We acknowledge that the distinction between known and unknown is not crisply defined.)"
- **Severe:** "misalignment that could plausibly contribute to one of our priority risk pathways." **Severity is pathway-relative, not magnitude-defined.**
- **Harm-inducing:** a computation that "must increase expected future harm above that coming from a baseline benign or null computation". Context-relative: vulnerable code in a dangerous-capabilities eval isn't harm-inducing; the same code in a real high-stakes task is. Can be delayed (exploited months later). Conceptually separate from misalignment (aligned computations can be harm-inducing via honest mistakes; misuse also). Harm need not be intended "provided it is caused by a sufficiently misaligned computation". Analysis confined to "potentially catastrophic harms".
- **High-stakes distribution:** "the distribution of inputs that provide opportunities to contribute to one or more of these threat pathways." Expected to change with capabilities and usage (cut off mid-sentence).

## Wandering

The engineered-by-prior-model clause is a sharp piece of causal bookkeeping: it moves model-to-model transmission of misalignment out of "naturally-emerging" (Claims 1–7) and into "engineered" (Claim 8). That matters because Anthropic trains models on data generated by prior models. If Mythos 5 inherited a misalignment from Mythos Preview's synthetic data, which claim covers it? Under fn 14, Claim 8 — *if* the prior's computations were misaligned *and* the effect foreseeable. If not foreseeable, it's naturally-emerging. So foreseeability decides the bucket. The project's sources-and-causes tree could use exactly this: a cause classified by intent *and* foreseeability.

"Severe = could plausibly contribute to a priority risk pathway" makes severity relative to the threat model's own pathway list. If Claim 7's pathway list were incomplete, a misalignment contributing only to an unlisted pathway would be *non-severe by definition*. So Claim 7 does real work: it guards the definition of severity. Expert-worthy point; I'll put it in questions.md.

"Harm-inducing" is defined with a counterfactual baseline: "a baseline benign or null computation". Third counterfactual baseline in the report (after other developers' systems; after 2023 models). Each is local to its concept. The project's lexicon should index baselines per term.

The eval-vs-real-task context dependence of harm-inducing is notable: the same act is harmless in an eval and harmful in deployment. This is why evaluation awareness (§2.16.3) is so central: a model that knows it's in an eval can behave well there, and the definitions don't by themselves catch the switch.

The duplicated known/unknown note: either the authors repeat it (plausible in a definitions section) or conversion duplicated text. Unit 21's version said "possible actions taken in pursuit of reward"; this one "possible actions these models might take in pursuit of reward" — slightly different wording, so likely a genuine authorial repeat (two drafts?). Not a conversion artifact, probably. Recording both readings.
