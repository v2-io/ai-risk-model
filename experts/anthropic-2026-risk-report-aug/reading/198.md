# Unit 198 — §4.5.5.4 Malicious access via prompt injection, L2555–2570, p.144

The scenario: an exempt agent with broad internet access meets injected content that steers it to do harmful bio work and upload results — no direct unsafeguarded API access needed by the attacker. Judged "extremely unlikely" to give meaningful uplift: (1) recent models fairly robust to prompt injection (System Card §5.2); (2) attentive authorised users would notice and report; (3) meaningful uplift needs sustained access over weeks/months (§4.2.3), hard to sustain unnoticed; (4) **natural experiment**: a large financial incentive already exists to build injection pipelines for *free ordinary usage*, which would be easier; none significant is known to have succeeded → barriers are prohibitive. (A commercially sensitive redaction on contractor population size is interposed.)

Differed: I predicted (unit 126) the report might connect reward-seeking dispositions to injection (Hacker-Opus answered harmful queries when shown a grading script). It doesn't here; the argument rests on general injection robustness. Different models (Hacker-Opus is an organism), so fair — but an expert could note the organism shows a disposition that would make injection easier if it arose in production.

Wandering: reason 4 is an elegant use of an observable counterfactual: if injection-for-free-compute hasn't worked despite strong incentives, harder injection-for-bio is less likely. Its weakness: free-usage pipelines need *scale*, bio needs only a few successful sessions with one exempt agent. The comparison favours the report's view but isn't a dominance argument. Marked as my observation.

Reason 3 reuses the "sustained access" premise again — the CB section's version of "many attempts". Three places now (Claim 5.1.1, §4.2.3, here).

Conversion: the redaction note splits the sentence "This … would not require…". Minor.
