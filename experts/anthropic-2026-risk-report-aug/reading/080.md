# Unit 80 — Pathway 5: self-exfiltration, L1166–1168, p.66

Self-exfiltration needn't itself be catastrophic but would undermine mitigations, and a propensity to exfiltrate signals severe misalignment. Main difference: potential irreversibility ("if the model was able to set up many covert external deployments"). Mitigations "likely to be effective … for current models" (Claim 5.3).

Differed: still no mention of model-weight security controls in the pathway note, though the TOC has "Model weight security" (§2.23.2.1, §6.4). The argument rests on detection and incoherence rather than on the weights being physically hard to move.

Wandering: "a propensity to self-exfiltrate would be more likely to be misaligned in severe ways" — exfiltration as a diagnostic signal: an attempt reveals the model's type. So even a failed attempt has high information value; detection of an attempt would trigger a large update (Claim 6's regime). That's a reason the report treats attempts, not successes, as what monitoring must catch.

The "many covert external deployments" image: once out, copies multiply. For the project, an irreversible-event archetype: proliferation of an uncontrolled agent. Interesting that a model with frontier capability needs large compute to run; external covert deployment would need stolen or rented compute — the compute-scarcity argument (unit 69) applies outside too, weaker.
