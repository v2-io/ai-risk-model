# Unit 193 — §4.5.5.2 Exemptions for sub-Mythos models, L2481–2499, p.141

- Unified exemption policy, criteria largely unchanged since February; **new: exempt customers attest to short-lived API credentials** (Workload Identity Federation). Every organisation manually vetted (harm potential, security posture). Ongoing monitoring + **monthly reassessment**.
- Classifiers run on all exempt traffic without blocking. **ZDR-enabled exempt organisations (<3% of active exemption seats)**: flagged traffic not viewable; only flag *rates* visible (fn 68).
- **No concerning bio activity identified; no exempt organisation offboarded since launch.**
- Temporary case-by-case exemptions for external safety-research collaborations (e.g. red-teaming), with security attestations (fn 69); far fewer than org-level.
- **Exceptions to the policy:** a small number, for time-sensitive beneficial uses (e.g. an ongoing public-health crisis) before the security review completes; explicit escalation and approval; usually **<40 seats**; expire unless renewed; all such cases either offboarded, later passed standard review, or expected to soon.
- Redactions for privacy/security.

Differed: the exception process is notable — the vetting control can be bypassed temporarily for urgent beneficial uses, with escalation and bounded seats. A disclosed override path.

Wandering: "no exempt org offboarded since launch" + "no concerning activity" can be read two ways (vetting works; monitoring is weak), just as §2's Bayesian note said of misalignment monitoring (unit 43). The report doesn't apply that caution here. An expert could.

The ZDR quantity (<3% of exemption seats) answers my unit-190 question: the set of exempt users with neither blocking nor content monitoring is small but non-zero; for them, only vetting and flag-rate visibility remain.

"Who decides" detail: exceptions require "explicit escalation and approval" — the approver isn't named. Same pattern as §2.18.
