# Unit 243 — §6.4.2 Notable security controls, L3088–3107, p.177

Ten controls: (1) egress bandwidth limits; (2) multi-party access (2PC) for weights; (3) binary allowlisting on employee devices; (4) hardware security keys (phishing-resistant MFA); (5) device authorisation; (6) cloud storage restrictions keeping weights inside the perimeter; (7) hourly re-authentication for privileged cloud identities; (8) network segmentation; (9) centralised security monitoring with anomaly detection; (10) network source policies (stolen tokens useless from outside approved networks). **Caveats on six of the ten redacted, without saying which six.** "Sophisticated insiders" defined: insiders with persistent or requestable time-limited access to systems processing weights.

Differed: the redaction method is clever — disclose that six of ten have hidden caveats without identifying them, so attackers can't target the weak ones. A redaction designed against inference.

Wandering: the definition of "sophisticated insiders" (anyone with persistent or requestable access to weight-processing systems) is broad — it includes ordinary engineers with such access, not just malicious experts. So "out of scope: sophisticated insiders" (unit 242) covers a sizeable population. Combined with the §3.10 insider standard ("even malicious employees … up to and including the company's CEO") and helpful-only model access (unit 195): the report's insider-threat defences are explicitly incomplete at three points. For the project: the source's own definition, worth carrying into any insider-risk mapping.

The controls list is standard enterprise security (the report says it aligns with SOC 2/ISO); AI-specific elements are egress limits for multi-terabyte weights and storage perimeter policies.
