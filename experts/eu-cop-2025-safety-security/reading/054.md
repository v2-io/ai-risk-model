# Unit 54 · L437–443 · p.20: M7.3(3) security; (4) the six-month look-ahead

**What it held.**
- "(3) a description of: (a) the Security Goal…; (b) all security mitigations implemented…; (c) how the mitigations meet the Security Goal, including the extent to which they align with relevant international standards or other relevant guidance (**such as the RAND Securing AI Model Weights report**); and (d) if Signatories have deviated from a listed security mitigation in… Appendices 4.1 to 4.5, points (a), a justification for how the alternative security mitigations… achieve the respective mitigation objectives; and"
- "(4) a high-level description of: (a) **the techniques and assets they intend to use to further develop the model over the next six months, including through the use of other AI models and/or AI systems**; (b) how such future versions and more advanced models may differ from the Signatory's current ones, in terms of capabilities and propensities; and (c) any new or materially updated safety and security mitigations that they intend to implement for such models."
- Conversion note: a page/column break splits (3)(c) across lines (L437–439). One sentence.

**What differed.**
- I predicted at unit 45 that the Code would avoid naming RAND. **Wrong**: the RAND *Securing AI Model Weights* report is named, as "relevant guidance" for alignment of security mitigations. The Code names a specific think-tank report. (It doesn't adopt RAND's security levels, though; just "the extent to which they align".)
- **(4) the six-month look-ahead**: not predicted. Every Model Report includes the provider's plans for the next six months of development, including **use of other AI models/systems** in that development, expected capability and propensity changes, and planned mitigations.

**Wandering.**

- **RAND as guidance.** Naming RAND gives that report quasi-normative standing: the Model Report must say how far the security mitigations align with it. RAND's report defines security levels SL1–SL5 by attacker capability (amateur → top state actors). So while M6.1 required protection only against non-state and insider threats by name, M7.3(3)(c) makes signatories report their security in a frame where nation-state protection is the top of the scale. The AI Office could see where each signatory sits on RAND's ladder. A fork should combine the two answers: no state-actor requirement by name (M6.1); reporting against RAND alignment (M7.3(3)(c)).
- **Correlation note**: RAND's report is also cited, I'd guess, by Anthropic's RSP, by SB 53 discussions, by IASR. It's a common ancestor of security talk across the corpus. Agreement about weight security across sources is shared lineage.
- **The six-month forecast is the model-level twin of the Framework's timeline forecast (M1.1(2)(c)).** Framework: when will we exceed our highest tier? Model Report: how will we develop this model over the next six months, with what, toward what capabilities and propensities, with what new mitigations? Again protected by recital (d): "information about future developments… understood as subject to change". The AI Office gets a rolling view of each lab's near-term roadmap. That's an unusually intimate regulatory window, more than most jurisdictions get.
- **"Including through the use of other AI models and/or AI systems"**: AI R&D automation again (cf. M7.1(2)). The Code repeatedly asks: are you using AI to build AI? It's watching for recursive acceleration, the scenario of the most concern in loss-of-control discussions, without naming it.
- **"Techniques and assets"**: assets likely means compute, data, talent? A broad word. And "further develop the model": post-market development of the *same* model (fine-tunes, new versions), consistent with recital (a).
- **"Propensities" in the forecast**: a lab must anticipate how propensities may differ in future versions, e.g. "more agentic RL training may increase reward-hacking propensities". That's demanding introspection, and a useful signal.

**Questions to keep.**
- "Does the Code require security against nation-state actors?" M6.1 names non-state external and insider threats only; M7.3(3)(c) requires reporting alignment with guidance "such as the RAND Securing AI Model Weights report".
- "Must providers disclose their development plans?" M7.3(4): for the next six months, the techniques and assets, including use of other AI models/systems; expected capability and propensity differences; planned new mitigations. To the AI Office, "subject to change" (recital (d)).
- Should be asked but might not be: "Does the Code track AI being used to accelerate AI development?" M7.1(2), M7.3(4)(a).

**Prediction for unit 55.** Measure 7.4, External reports: Signatories will include in the Model Report (or provide links to) the reports of independent external evaluators (Appendix 3.5) and of independent security reviews, with an explanation if none were used (e.g. the model is similarly safe or safer, or no suitable evaluator was available). Possibly a requirement to report external evaluators' disagreements with the provider.
