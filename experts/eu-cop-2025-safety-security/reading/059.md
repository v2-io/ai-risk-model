# Unit 59 · L485–488 · p.22: M7.6, contents of an updated Model Report

**What it held.** "The updated Model Report will contain: (1) the updated information specified in Measures 7.1 to 7.5 **based on the results of the full systemic risk assessment and mitigation process** (pursuant to Measure 1.2, third paragraph); and (2) a **changelog**, describing how and why the Model Report has been updated, along with a version number and the date of change."

**What differed.** I'd predicted M7.7 next; M7.6 had one more paragraph. Its content confirms Figure 2 in text: every update rests on a **full** systemic risk assessment. And the changelog mirrors M1.3's Framework changelog.

**Wandering.**
- **Every update is a full update**, not a patch. Information under M7.1–7.5 is refreshed from a full process. With the non-duplication clause (M1.2: reuse parts still appropriate), the full process can be light where nothing changed, but formally it's full. A fork asked "is a Model Report update a delta or a new report?" should say: an updated report with all M7.1–7.5 information, plus a changelog.
- **Changelogs, twice.** Framework and Model Report both carry version numbers, dates, and how/why. The AI Office can track drift in both. If these were ever made public (they aren't, under this Chapter), they'd be extraordinary sources for a project like ours: a dated, reasoned history of each lab's risk claims.
- **"Measure 1.2, third paragraph"** is cited here for the full process. Earlier (unit 16) the reference was to M1.2's paragraph introducing the four-step process. So the Code numbers M1.2's paragraphs as: first ("will implement the processes…"), second ("along the entire model lifecycle… continuously"), third ("In addition… full systemic risk assessment and mitigation process"). And unit 58's reference to "Measure 1.2, second paragraph" for continuous assessment fits. Good: the cross-references are internally consistent, which matters for forks that resolve them.
