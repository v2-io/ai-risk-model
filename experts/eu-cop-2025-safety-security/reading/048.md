# Unit 48 · L400–409 · p.19: Measure 7.1, Model description and behaviour (first part)

**What it held.** "Signatories will provide in the Model Report:
1. a high-level description of the model's architecture, capabilities, propensities, and affordances, and how the model has been developed, including its training method and data, as well as **how these differ from other models they have made available on the market**;
2. a description of how the model has been used and is expected to be used, **including its use in the development, oversight, and/or evaluation of models**;
3. a description of the model versions that are going to be made or are currently made available on the market **and/or used**, including differences in systemic risk mitigations and systemic risks; and
4. a specification (e.g. via valid hyperlinks) of how Signatories intend the model to operate (often known as a "**model specification**"), including by:
   - (a) specifying the principles that the model is intended to follow;
   - (b) stating how the model is intended to **prioritise different kinds of principles and instructions**;" (continues)

**What differed.** Predicted architecture/capabilities/training, use, versions, model spec. Not predicted:
- (2)'s **use of the model in the development, oversight, and/or evaluation of models**: the AI-R&D use case, named. Internal use for building, monitoring and testing other models must be described.
- (1)'s **comparison with the signatory's previous marketed models**: what's new.
- (4)(b)'s **prioritisation of principles and instructions**: the instruction hierarchy (system vs developer vs user), required to be stated.

**Wandering.**

- **This partly corrects my internal-deployment picture.** I'd said "no Model Report for internal-only models" (unit 47). That stands: the Model Report is created before market placement. But *within* a Model Report, the signatory must describe how the model "has been used and is expected to be used, including its use in the development, oversight, and/or evaluation of models", and versions "used" (not only marketed). So internal use of a *marketed* model is reported, including in AI R&D. A model that is never marketed is still outside the Model Report. The precise answer: the Model Report covers internal uses of models that are placed on the market; models used only internally have no Model Report.
- **"Development, oversight, and/or evaluation of models"** is the loss-of-control-relevant use: AI doing AI R&D, AI monitoring AI, AI grading AI. These are exactly the uses where a misaligned model could sabotage oversight or accelerate capability. The Code's drafters clearly know this and made it reportable.
- **The model spec as a reporting element.** "Often known as a 'model specification'": OpenAI's Model Spec and Anthropic's constitution-style documents are the referents. The Code requires one, at least for the Model Report: principles the model follows, how it prioritises among principles and instructions. "E.g. via valid hyperlinks" suggests the drafters expect model specs to be public documents that can be linked. A public model spec might thus become standard via the Code. (Correlation note: this is the labs' own practice written into the Code.)
- **Why does a systemic-risk report need a model spec?** Because intended behaviour defines what counts as deviation (a propensity to break its spec is a risk indicator), and because the prioritisation of instructions determines manipulation and misuse resistance (a model that prioritises user instructions over safety principles is more easily misused). It's also the place where a model's intended stance on oversight (accept shutdown? defer to developers?) would be stated.
- **"Valid hyperlinks"**: a small, practical, almost comic detail; someone worried about dead links in regulatory submissions.

**Questions to keep.**
- "Does the Model Report cover internal use?" It must describe how the model "has been used and is expected to be used, including its use in the development, oversight, and/or evaluation of models", and versions "used". But there's no Model Report for a model never placed on the market (C7).
- "Does the Code require a model specification?" M7.1(4): the Model Report includes "a specification… of how Signatories intend the model to operate (often known as a 'model specification')", with principles and their prioritisation.
- Should be asked but might not be: "Does the Code require disclosure of AI being used to build or oversee AI?" Yes, M7.1(2).
