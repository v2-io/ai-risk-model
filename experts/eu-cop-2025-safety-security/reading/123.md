# Unit 123 · L979–988 · p.43: Appendix 4.5, Security assurance (1)–(6)

**What it held.** "Signatories will obtain assurance that their security mitigations meet the Security Goal by implementing additional security mitigations that achieve the following mitigation objectives:
1. **independent external validation** of security mitigation effectiveness **if internal expertise is inadequate**, through (a) regular independent external security reviews as appropriate to mitigate systemic risks;
2. validation of network and physical access management and security gap identification, through (a) **frequent red-teaming** as appropriate…;
3. validation of network software integrity, through (a) competitive **bug bounty** programs… of public-facing endpoints as appropriate…;
4. validation of insider threat security mitigations, through (a) **periodic personnel integrity testing**;
5. facilitation of reporting of security issues, through (a) secure communication channels for third parties to report security issues;
6. detection of suspicious or malicious activity, through (a) installation of **Endpoint Detection and Response ("EDR") and/or Intrusion Detection System (IDS)** tools on all networks and devices; and" (continues)

**What differed.** Predicted: external reviews, red-teaming, bug bounties, reporting channels, detection. Not predicted, and important: **external security review is conditional**, "**if internal expertise is inadequate**". And **personnel integrity testing** (e.g. testing whether staff follow security procedures under pretext).

**Wandering.**
- **The external security review is weaker than M7.4 implied.** M7.4(1)(b) asked for reports from "security reviews undertaken by an independent external party pursuant to Appendix 4.5". Here such reviews are required only "if internal expertise is inadequate". A large lab with a strong internal security team could argue it needs no external review. That's a notable softness compared with the default external *model* evaluation (Appendix 3.5). A fork should contrast: external model evaluation is the default (with exceptions); external security review is conditional on inadequate internal expertise.
- **"As appropriate to mitigate systemic risks"** qualifies (1)–(3). Glossary 'appropriate' makes these demanding ("suitable and necessary… state of the art… beyond"), but the conditional "if internal expertise is inadequate" in (1) is a structural limit no definition overrides.
- **Personnel integrity testing**: social-engineering tests of staff, in effect. Validates insider-threat mitigations. Combined with background checks (4.4(1)), the human side is covered.
- **EDR/IDS on "all networks and devices"**: baseline monitoring, universal scope.
- **(5) third-party reporting channels** for security issues: the security analogue of M9.1(2) and M3.5(5).

**Questions to keep.**
- "Is independent external security review required?" Appendix 4.5(1): only "if internal expertise is inadequate", through "regular independent external security reviews as appropriate to mitigate systemic risks". Contrast Appendix 3.5's default external model evaluation.
- "What security assurance does the Code require?" Appendix 4.5: external review (conditional), frequent red-teaming, bug bounties for public endpoints, periodic personnel integrity testing, third-party reporting channels, EDR/IDS on all networks and devices; (continues).

The canonical text may end with the Appendix.
