# Unit 65 · L125 · p.5

> (k) "Model weight" means a numerical parameter in a frontier model that is adjusted through training and that helps determine how inputs are transformed into outputs.

## What differed

As predicted. There's a page break (L121 → L125, p.4 → p.5).

## Wandering

- "In a **frontier** model": the term is scoped to frontier models only. Weights of a foundation model below threshold aren't "model weights" under the TFAIA. That works inside the incident definition (d)(1) ("model weights of a frontier model"), though it's redundant there.
- A model *defined as a system* (u40) contains numerical parameters. The definition quietly treats the model as weights-bearing, so it's an artifact with parameters. So the system/weights slide is real, and the statute moves between the two without noticing. For practical purposes: a frontier model is a system whose core is a weights-bearing network.
- "Adjusted through training" excludes hyperparameters and architecture constants. Do embeddings count? Yes, they're trained. LoRA adapters are trained parameters "in" the model once merged; unmerged, arguably in a separate artifact. Edge case for (d)(1) modification.
- "Helps determine how inputs are transformed into outputs" is a functional description. Fine.
