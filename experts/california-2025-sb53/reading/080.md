# Unit 80 · L140 · p.5

> (c) (1) Before, or concurrently with, deploying a new frontier model or a substantially modified version of an existing frontier model, a frontier developer shall clearly and conspicuously publish on its internet website a transparency report containing all of the following:

## What differed

As recalled. The tier is confirmed: **"a frontier developer"**, so every frontier developer owes a transparency report, not only large ones.

## Wandering

- **Tier map so far:**
  - framework (a), annual review (b)(1), publishing modifications (b)(2): **large** frontier developers;
  - transparency report (c): **all** frontier developers.

  So a small lab with a frontier model publishes a transparency report at deployment but no framework. That's the proportionality design in action. A summary saying "SB 53 requires large developers to publish transparency reports" is wrong in scope; it's all frontier developers. The large tier probably adds content to the report (a second paragraph listing framework-related items). That's a common structure: (c)(1) for all, (c)(2) for large ones.
- **"Before, or concurrently with"**: the report can be published the moment of deployment, not necessarily before. No advance notice, so no pre-deployment review by anyone. Transparency here is *contemporaneous*, not *prior*.
- **"A new frontier model or a substantially modified version of an existing frontier model"**: "substantially modified" is the trigger from (a)(6), where the large developer's framework defines its criteria. But a *small* frontier developer has no framework, so who decides what's "substantially modified" for it? The statute is silent: ordinary meaning. So the trigger is self-defined for large developers and undefined for small ones.
  - "Substantially" is a new qualifier alongside "materially". Related but distinct? A "material modification" (to the framework, (b)(2); to training, (i)(2)) vs "substantially modified" (model, here). Probably different standards for different objects.
- "Deploying" as defined in (e): third-party availability, excluding evaluation. So an internal-only model needs no transparency report, however extensively used. Internal use goes to the framework and OES; deployment goes to the public. The two information channels split along the internal/external line, as I'd thought.
