## Wandering

- **Here weight security is a framework topic, with no injury condition.** Compare incident item (d)(1), where theft counted only if it "results in death or bodily injury". So SB 53 addresses weight security *preventively* (the framework must describe how the developer secures unreleased weights, and the developer must comply). It addresses theft *reactively* only once theft hurts someone. **What closes the u50 gap:** a lab whose weights are stolen through a security failure has, if it had committed to practices it didn't follow, *violated its framework*. That's noncompliance with §22757.12(a), subject to AG enforcement, and a whistleblower prong (b) matter. So weight theft without injury isn't a reportable incident, but it may be *evidence of a TFAIA violation* through the framework. That's a real answer to "what happens under SB 53 if weights are stolen?". Not a mandatory OES report, unless it causes injury. Possibly an enforcement matter, if the developer didn't do what its framework said.
- "**Unreleased**" model weights: once released (open weights), there's nothing to secure. "**Internal or external parties**": insider threat is named. "**Modification or transfer**": transfer covers exfiltration; modification covers tampering. That parallels (d)(1)'s "access … modification … exfiltration", though "access" alone isn't here. (Unauthorized *access* without transfer, someone browsing weights, is in the incident list but not in this framework topic.)
- "**Cybersecurity practices**", not "security practices". Physical security and personnel security (vetting) aren't named. RAND's weight-security levels cover all three. A narrow framework could cover only cyber.
