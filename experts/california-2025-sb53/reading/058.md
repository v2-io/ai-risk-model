## Wandering

- "**Designed** for" is an intent test: what the developer designed it for. A model trained broadly, but marketed and "designed" for one narrow use (a coding-only model, a math-only model), might escape on design intent even if it's in fact general. An emergent-generality model designed for narrow purposes is the edge case. The developer's own characterization matters again (as with "primary purpose" in deploy). **Pattern: several SB 53 scope tests turn on the developer's stated purpose or design.** That's a structural feature worth recording in the source model: it relies on developer self-characterization for scope as well as for content.
- "Generality of output" is about the outputs being general, not the training. A model that produces only code (output narrow) but understands everything? Probably still general enough. It's vague.
